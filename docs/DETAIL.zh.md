# 会话内查找

`@local/dsh-find-in-session` 在打开的会话上放一条查找条。它和 1.0.0 里那条是同一条——这次发布把「它报告的数字」做成真的，而不是把它做大。

## 它能做什么

- **Ctrl+F / Cmd+F** 开关键；**Esc** 关闭并把焦点还给打开前的位置。侧栏底部的入口是给鼠标走的路。
- 输入即在已渲染的会话正文里高亮全部命中。**Enter** 或 **F3** 下一处，
  **Shift+Enter** / **Shift+F3** 上一处，**Ctrl+G** 也能循环。
- 打开查找条时若会话里有选中文字，会用它作为查询的种子（最多 200 字符）。

## 匹配语义：与宿主完全一致

查询的编译方式与宿主自己的会话文本过滤（`@deepseek-ai/dsh-session-query` 的
`compileSessionTextFilter`）逐字等价：

- 大小写不敏感；
- 词与词之间的空白是弹性的——`hello world` 能命中 `hello\t\tworld` 与换行，
  但不会命中 `helloworld`；
- 其余一律按字面量。输入 `.*` 找的是一个点加一个星号，不会变成通配符。

`verify.mjs` 会把同一组探针字符串分别喂给本插件的编译器与**从安装包 `app.asar` 里读出来的**宿主编译器，正则表达式不一致即失败。

## 计数是诚实的

条上的数字是会话里真实的命中总数。绘制高亮不是免费的——`new Highlight(...ranges)` 每个命中一个实参——所以最多绘制 4000 处。到达该上限时条上会明说（`2/5000，已高亮 4000 处`），侧栏计数带上 `+`。没有任何命中被静默丢弃；如果浏览器没有 CSS Custom Highlight API，条上会说明「无法高亮」，而不是假装零命中。

## 往前翻页是宿主的事

当前窗口里没有命中时，查找条会去点宿主自己的「加载更早」控件——`[data-chat-history]` 里的那个按钮——然后重新搜索，最多 8 页。它自己从不实现分页：接在前面的补页、滚动锚定、重分页都归宿主，第二个实现只会和它打架。`verify.mjs` 会断言宿主仍在渲染那个控件，并且本插件没有调用任何自己的分页 API。

## 颜色跟随主题

四个高亮颜色通过 `theme.overrideTokens` 注册成主题令牌，深浅两套配色都保持可读。查找条自身的文字**不由本插件上色**——用的是宿主的
`--dsw-alias-label-*` 令牌——`verify.mjs` 会用安装包里的实际取值重算这两组对比度：

- 高亮组：最弱是深色主题下的当前命中，6.45:1；
- 条与侧栏的文字：最弱是侧栏次级文字，5.55:1。

全部达到 WCAG AA（4.5:1）。三级文字色只用在禁用按钮上，因为它在浅色主题下只有 3.71:1——对"点不动的东西"够用，对"必须读的句子"不够。

## 它刻意不做什么

- **不读会话事件日志。** 只匹配会话列真正渲染出来的文字。工具调用的原始参数、请求头，以及任何正文没画出来的东西，都不在范围内——那由宿主自己的会话搜索负责，这条查找条不冒充能做。
- **不搜控件里的字。** 候选只来自文本节点，且落在 `button`、`input`、`select`、`option`、`textarea`、`script`、`style`、`[aria-hidden="true"]`、`[data-chat-history]`、`[data-chat-turn-spacer]`、`[data-text-interaction-surface]` 之下的节点一律跳过。转写区自带按钮上的文字因此搜不到：那是界面外壳，不是对话内容，把它们算进命中会让计数取决于恰好有哪些控件在屏幕上。
- **不跨会话。** 一次只搜当前这一段会话。
- **查找条不能拖动、停靠或折叠。** 它固定在会话头部下方、右对齐聊天列，列宽变化（打开右栏、折叠侧栏、拖分隔条）时重新测量——这些都不触发 `window.resize`，所以用 `ResizeObserver` 盯住列本身。它会遮住正文最上面一条消息的一小部分，这是不往宿主布局里塞容器的代价。
- **不新增命中列表、设置页、第二个搜索框或独立窗口。** 一条条、一个侧栏入口、同一套快捷键。
- **不实现正则、全词匹配或大小写敏感开关。** 宿主只有一套字面量语义，对齐它才是重点。
